# v0.1.0-alpha Release Checklist

This checklist defines the first alpha release target.

The purpose of v0.1.0-alpha is to publish a safe, auditable infrastructure prototype.

It is not real biometric authentication yet.

## Release goals

v0.1.0-alpha should demonstrate:

- daemon architecture
- camera access
- user-level IPC
- PAM IPC bridge
- fail-closed auth behavior
- fake PAM testing
- systemd user service
- encrypted template storage scaffold
- Python prototyping tools
- CI build
- Debian package artifact

## Required before release

Repository:

- [ ] README is accurate.
- [ ] SECURITY.md is accurate.
- [ ] ROADMAP.md is accurate.
- [ ] docs/project-status.md is accurate.
- [ ] docs/pam-safety.md is accurate.
- [ ] docs/pam-fake-service-test.md is accurate.
- [ ] docs/systemd-user-service.md is accurate.
- [ ] docs/packaging.md is accurate.

Build and CI:

- [ ] GitHub Actions build passes.
- [ ] CMake local build passes.
- [ ] CTest passes.
- [ ] Debian package builds locally.
- [ ] Debian package builds in CI.
- [ ] CI artifacts upload correctly.

Local validation:

- [ ] daemon one-shot camera probe works.
- [ ] daemon loop mode works.
- [ ] daemon mode creates socket.
- [ ] socket test client ping works.
- [ ] camera_status operation works.
- [ ] auth fails closed by default.
- [ ] max auth attempts are enforced.
- [ ] development-only auth works only with FACE_UNLOCK_DEV_ALLOW=1.
- [ ] crypto self-test passes.
- [ ] Python prototype runs without saving by default.
- [ ] Python prototype refuses to save crops without explicit privacy flag.

PAM validation:

- [ ] pam_face_unlock.so builds.
- [ ] pam_face_unlock.so does not link OpenCV.
- [ ] pam_face_unlock.so does not link Torch.
- [ ] pam_face_unlock.so does not link Qt.
- [ ] pam_face_unlock.so does not link CUDA.
- [ ] fake PAM service test falls back to password by default.
- [ ] fake PAM service test succeeds with development auth enabled.
- [ ] fake PAM rollback removes test service and module.

systemd validation:

- [ ] user service install script works.
- [ ] user service starts daemon.
- [ ] user service creates socket.
- [ ] user service keeps auth fail-closed by default.
- [ ] user service removal script works.
- [ ] user service removal removes socket.

Packaging validation:

- [ ] dpkg-deb -c output is reviewed.
- [ ] dpkg-deb -I metadata is reviewed.
- [ ] package install is not required for release, but package contents must be inspectable.
- [ ] package does not contain biometric data.
- [ ] package does not include generated model files.
- [ ] package does not automatically modify PAM service files.

Security checks:

- [ ] no raw face images committed.
- [ ] no enrollment_samples directory committed.
- [ ] no templates committed.
- [ ] no .enc biometric files committed.
- [ ] no model artifacts committed.
- [ ] no secrets committed.
- [ ] PAM module remains minimal.
- [ ] rollback instructions exist for all scripts that touch system paths.

## Explicit non-goals for v0.1.0-alpha

v0.1.0-alpha will not provide:

- real face recognition authentication
- production sudo integration
- lock-screen integration
- login greeter integration
- Qt enrollment GUI
- liveness detection
- calibrated thresholds
- secure real template enrollment

## Manual verification commands

Run docs check:

    ./scripts/check-docs.sh

Build:

    ./scripts/build.sh

Run tests:

    ./scripts/test.sh

Run camera probe:

    ./build/daemon/face-unlockd --camera 0

Run daemon mode:

    ./build/daemon/face-unlockd --camera 0 --daemon

In another terminal:

    ./scripts/test-socket-client.sh ping
    ./scripts/test-socket-client.sh camera_status
    ./scripts/test-socket-client.sh auth

Run crypto self-test:

    ./build/daemon/face-unlock-crypto-selftest

Build package:

    ./scripts/package-deb.sh

Inspect package:

    dpkg-deb -c build/*.deb
    dpkg-deb -I build/*.deb

## Release notes draft

v0.1.0-alpha is the first infrastructure alpha release of face-unlock-linux.

It includes a user daemon, camera prototype, local UNIX socket IPC, minimal PAM module, fake PAM test flow, systemd user service helpers, encrypted template storage scaffold, Python prototyping tools, optional TorchScript loader scaffold, CTest, CI, and Debian package generation.

This release does not implement real biometric authentication yet.

Do not use it as a real authentication method.
